# Pricing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web screen that shows, for every active manufactured product with a recipe, its cost per unit (from ingredient stock average costs) and its price per unit (cost plus an editable markup).

**Architecture:** One pure fixed-point module in `src/shared/pricing.ts` computes cost and price for both the server and the browser preview. A new `pricing` server module owns the `product_markups` table and builds the rows; a Server Component page reads them and a Server Action saves the markup. No REST route.

**Tech Stack:** Next.js 16 App Router, Prisma/Postgres, zod 4, Vitest (jsdom + node), Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-07-pricing-design.md`

## Global Constraints

- Code, identifiers, comments and tests in English; UI text in Portuguese.
- **Do not commit.** The user commits. Each task ends with the tree dirty and its checks green.
- TDD: every test is run red, and the red output is pasted, before the code that turns it green.
- Business rules live in `pricing.service.ts`; the action is an adapter. `pricing.schemas.ts` never imports `@prisma/client`.
- Decimals travel as strings; no amount passes through a JS `number`.
- Markup is a percentage string: `0` to `1000`, at most 2 decimal places (`35.00` = 35 %).
- Price = cost/un × (1 + markup/100), **rounded up** to the cent. Cost/un = Σ(quantity × averageCost) ÷ yield, rounded half-up to 6 decimal places.
- Any ingredient with no average cost → status `incomplete-cost`; never a partial cost, never zero.
- Permissions: `PRICING_READ` (screen), `PRICING_UPDATE` (edit markup).
- No Postgres in this WSL: integration tests are written but cannot run locally — say so when reporting.
- Verification per task: `npx vitest run <files>`, `npm run typecheck`, `npx eslint <files>`.

## Review Focus

1. Markup typed the Brazilian way (`35,5`, `1.000`) — the preview and the save must read it through `toApiDecimal`, not `Number()`. → Task 5, test "reads a comma markup".
2. Markup the schema refuses (`abc`, `1000,01`, `-1`, three decimals) — the preview shows "—", the save is not called and the field shows an error. → Task 5, test "refuses an invalid markup without calling the action".
3. An ingredient with no `product_stocks` row at all (never entered) — must be `incomplete-cost` just like a row with `average_cost` null. → Task 3, service test "treats a missing stock row as missing cost".
4. Editing the markup of one row must not touch the draft or the price of another row. → Task 5, test "keeps each row's draft separate".
5. A cost that needs more than 6 places in the intermediate product (6-place quantity × 6-place cost) — exact before rounding. → Task 1, test "keeps 12 places in the product before rounding".

### Task 1: Pure cost and price calculation

**Files:**
- Create: `src/shared/pricing.ts`
- Test: `src/shared/pricing.test.ts` (runs in the `api` project)

**Interfaces:**
- Produces:
  ```ts
  export type IngredientCost = { productSku: string; quantity: string; averageCost: string | null };
  export type CostResult =
    | { status: "complete"; costPerUnit: string }      // 6 decimal places, e.g. "1.230000"
    | { status: "incomplete"; missing: string[] };     // productSku of each ingredient without cost, in input order
  export function costPerUnit(input: { yieldQuantity: string; ingredients: IngredientCost[] }): CostResult;
  export function ingredientSubtotal(quantity: string, averageCost: string): string; // quantity × cost, 6 places half-up
  export function priceFor(costPerUnit: string, markupPercent: string): string;      // 2 places, rounded up
  ```

- [ ] **Step 1: Write the failing tests**

```ts
describe("costPerUnit", () => {
  it("sums quantity × average cost and divides by the yield", () => {
    expect(costPerUnit({ yieldQuantity: "10", ingredients: [
      { productSku: "a", quantity: "2", averageCost: "5.5" },
      { productSku: "b", quantity: "0.5", averageCost: "8" },
    ] })).toEqual({ status: "complete", costPerUnit: "1.500000" });
  });
  it("is incomplete when any ingredient has no average cost, never partial", () => {
    expect(costPerUnit({ yieldQuantity: "10", ingredients: [
      { productSku: "a", quantity: "2", averageCost: "5.5" },
      { productSku: "b", quantity: "1", averageCost: null },
    ] })).toEqual({ status: "incomplete", missing: ["b"] });
  });
  it("keeps 12 places in the product before rounding", () => {
    // 0.333333 × 0.000003 = 0.000000999999 → ÷1 → 0.000001 (half-up at 6 places)
    expect(costPerUnit({ yieldQuantity: "1", ingredients: [
      { productSku: "a", quantity: "0.333333", averageCost: "0.000003" },
    ] })).toEqual({ status: "complete", costPerUnit: "0.000001" });
  });
  it("is exact where floating point is not", () => {
    expect(costPerUnit({ yieldQuantity: "1", ingredients: [
      { productSku: "a", quantity: "1", averageCost: "0.1" },
      { productSku: "b", quantity: "1", averageCost: "0.2" },
    ] })).toEqual({ status: "complete", costPerUnit: "0.300000" });
  });
});

describe("ingredientSubtotal", () => {
  it("multiplies quantity by cost at 6 places", () => expect(ingredientSubtotal("2.5", "1.1")).toBe("2.750000"));
});

describe("priceFor", () => {
  it("rounds up to the cent", () => expect(priceFor("1.231", "0")).toBe("1.24"));
  it("leaves an exact cent alone", () => expect(priceFor("1.230000", "0")).toBe("1.23"));
  it("applies the markup over the cost", () => expect(priceFor("2.000000", "35")).toBe("2.70"));
  it("applies a fractional markup", () => expect(priceFor("1.000000", "12.5")).toBe("1.13"));
});
```

- [ ] **Step 2: Run red** — `npx vitest run src/shared/pricing.test.ts` → FAIL, cannot resolve `@/shared/pricing`. Paste output.

- [ ] **Step 3: Implement in `src/shared/pricing.ts`**

Parse each decimal string into a `BigInt` scaled by 10^6 (quantities, costs) or 10^2 (markup). Products of two 10^6 values are 10^12; divide back with an explicit rounding helper. Division of the 10^12 sum by the 10^6 yield gives 10^6 with half-up rounding. For the price: `cost(10^6) × (10000 + markup(10^2))` is scaled 10^10; ceil-divide by 10^8 to reach cents. Format back with a fixed number of places. No `Number()` anywhere.
